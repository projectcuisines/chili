To run the input files for MAGMAVOL, you need to have both VapoRock and FastChem installed since MAGMAVOL is basically a coupling between those two packages.

_______________________________________________________________________________________________________________________________

1. VapoRock installation

For installing VapoRock, please see instructions at https://gitlab.com/ENKI-portal/vaporock/-/tree/thermoenginelite-port?ref_type=heads for the thermoenginelite-port branch. ThermoEngine necessary to run VapoRock can technically already be installled by doing:

pip install thermoengine

The pip installable version of VapoRock cannot tecnically be used, so one has to clone the branch specific VapoRock repository and then install that version specifically.

_______________________________________________________________________________________________________________________________ 

2. FastChem installation

FastChem can be easily installed by running

pip install pyfastchem

but I recommend cloning the repository at https://github.com/NewStrangeWorlds/FastChem and then installing by doing

python3 setup.py install

For detailed instructions, please see here: https://newstrangeworlds.github.io/FastChem/sections/installation.html

_______________________________________________________________________________________________________________________________

When both have been installed, clone the MAGMAVOL repository at https://github.com/dashspandan/MAGMAVOL. Then switch to the chili specifc branch by doing

git switch chili

Read the installation instructions and instructions to download the reservoir of solutions in the README page provided and test if MAGMAVOL works with all necessary modifications.

Once it is confirmed that MAGMAVOL works, the CHILI repository can be cloned somehwere and the location of the intercomparison file mentioned at the start of both the run_magmavol scripts present in the MAGMAVOL directory. The Fastchem folders paths and the paths to the MAGMAVOL directory and the reservoir of solutions also needs to be changed. 

For this particular case, the MAGMAVOL is run is the scenario where the melt of some fO2 is able to completely buffer the atmosphere above it. The melt fO2 is obtained from the evolutionary model outputs, or calculated from the pO2 of the atmosphere if the melt fO2 is not provided. If both information are absent, a default value of IW+4 is used to run MAGMAVOL in the TARGET_FO2 mode.

For specific cases, comment out the cases in _main_ which you don't need to run and then simply run the script using:

python3 run_magmavol_meltfug.py

An alternate way is to simply go to the input folder for magmavol_meltfug of the CHILI directory in intercomparison. Uncommenting out all cases except for what you need and then running each of the input scripts is also doable provided that the process above is also done.

4. Inputs ingested from the evolutionary models

For each (planet, tau, hot/cold) combination, MAGMAVOL ingests the following quantities from the evolutionary model output CSV at the time step closest to the requested tau:

- T_surf (K): the magma ocean surface temperature, used as the thermal boundary condition for the atmosphere-melt equilibrium calculation.
- massH_atm (kg) and massC_atm (kg): the atmospheric hydrogen and carbon masses, converted to partial pressures in bar using the planet's surface gravity and radius (homogenised CHILI values) and passed as initial and target atmospheric H and C pressures respectively.

In principle massO_atm (kg) is also available and was converted to an oxygen pressure in bar by the same procedure. However, in the TARGET_FO2 mode used here the total atmospheric oxygen content is entirely determined by the imposed melt fO2 (see section 6 below), so the pre-existing oxygen inventory has no effect on the converged solution. Accordingly, the initial atmospheric oxygen is set to zero for this scenario, and only C and H are used as effective inputs.

_______________________________________________________________________________________________________________________________

5. Pressure budget and silicate vapour

In several cases, particularly at high surface temperatures, the sum of the partial pressures reported in the CHILI output columns (H2O, CO2, CO, H2, CH4, O2) is substantially less than p_tot. The remainder consists of refractory vapour species — oxides and elemental vapours of Si, Mg, Fe, Na, K, Ca, Al and related species — produced by VapoRock's magma ocean evaporation model at the high surface temperatures involved. These species do not have dedicated columns in the CHILI static output format and are therefore not reported individually. The discrepancy is largest in the hottest cases: for example, at trappist1alpha tau3-hot (T_surf ~ 3500 K) refractory vapours accounts for the majority of p_tot. This is a physically expected result at these temperatures and does not represent a mass-balance error; the full elemental inventory is conserved within the MAGMAVOL calculation.

_______________________________________________________________________________________________________________________________

6. Oxygen-rich cases and the melt fO2 assumption

In a number of cases, O2 constitutes a dominant fraction of the reported atmosphere (for example, O2 is approximately 76% of the atmosphere at earth tau3-hot, 78% at venus tau3-hot and trappist1alpha tau3-cold, and 99% at trappist1alpha tau4-cold). This is a direct consequence of the physical scenario this submission represents.

In the TARGET_FO2 mode, the melt is assumed to be a perfect redox buffer: the melt fO2 fixes the O2 partial pressure of the atmosphere above it, and the FastChem equilibrium chemistry then distributes the elemental inventory across all species at that imposed oxidation state. The target fO2 is taken in priority order from (1) the fO2_melt(bar) column of the evolutionary model output, converted to a deviation from the IW buffer; (2) the p_O2(bar) column if fO2_melt is unavailable; (3) a default of IW+4 if neither is provided. This approach follows Seidler et al. (2024, A&A, 691, A208) and Seidler et al. (2026, A&A, 700, A140), where the same assumption is applied to ultra-hot rocky exoplanet atmospheres.

At the temperatures and fO2 values relevant to the early magma ocean stage (IW+4 or above), the equilibrium chemistry drives a large fraction of the available oxygen into the gas phase as O2 rather than into H2O or CO2, because the H and C inventories at these tau values are relatively small compared to the total oxygen implied by the imposed fO2. The oxygen-rich composition is therefore a self-consistent outcome of the imposed melt buffering assumption, not an artefact.

_______________________________________________________________________________________________________________________________

7. Total pressure

The p_tot reported in the CHILI output files is not an input to MAGMAVOL. It is an output: MAGMAVOL takes the elemental inventories (H and C in bar, derived from the evolutionary model masses as described in section 4, plus the melt fO2 target) and solves the atmosphere-melt chemical equilibrium self-consistently, producing p_tot as a result of the converged solution. The input surface pressure p_surf from the evolutionary model is therefore not carried forward and p_tot will in general differ from it, sometimes substantially, because the two quantities represent different physical states: p_surf is the pressure at the end of the evolutionary model's own calculation, while MAGMAVOL's p_tot is the pressure of a new static equilibrium computed at T_surf with the given elemental inventory and melt fO2.
